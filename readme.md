# HH Assistant — памятка

Простыми словами: что это, как запустить и что где лежит.

## Что делает

1. Раз в 30 минут заходит на hh.ru и ищет новые вакансии по моим фильтрам — три поиска:
   Vue/Nuxt-фронтенд, всё про ИИ (LLM, нейросети, AI-агенты, вайб-кодинг) и разработка на любом стеке
   (React, Angular, бэкенд), если в вакансии есть ИИ. В каждом письме — «основной стек Vue и Node, но с ИИ пишу на любом».
2. Сразу отбрасывает лишнее: где больше 500 откликов или зарплата явно ниже 80 000 ₽.
3. Остальное отдаёт нейросети (Groq, модель Qwen). ИИ сверяет вакансию с моим профилем из `profile.md`.
   Первыми смотрит вакансии, где меньше всего откликов.
4. Если вакансия подходит — присылает в Telegram:
   - кратко, что требуют;
   - черновик сопроводительного письма — **нажимаешь на текст, и он копируется целиком**;
   - кнопки: **Открыть вакансию**, **Я отправила отклик**, **Пропустить** (бот смотрителя, сообщения помечены 🟦 HH).
5. Откликаюсь я сама, вручную на hh.ru. Бот ничего не отправляет от моего имени.
6. **Я отправила отклик** — сообщение исчезает, вакансия с датой сохраняется в базе.
   **📋 Отклики HH** (кнопка внизу бота смотрителя) — список: название-ссылка и дата,
   по 10 штук, листается кнопками 1, 2, 3…

Отдельной кнопки «Скопировать» нет: кнопка копирования в Telegram берёт максимум 256 символов, а письмо длиннее.

## Главное

- **Порт:** 3002 (у kwork-бота — 3001, они не мешают друг другу).
- **Проверить, что работает:** открыть http://127.0.0.1:3002
- **База данных:** PostgreSQL 16 в Docker — контейнер `hh-postgres`, порт 5435, база `hh_assistant`. Запускается сама вместе с Docker. Пароль — в `.env`.
- **Telegram-бот:** общий со смотрителем (MAIN_ASSISTANT). HH только отправляет сообщения;
  нажатия кнопок принимает смотритель и пересылает сюда (`POST /bot/callback`, `/bot/command`).
  «📋 Отклики HH» — кнопка внизу бота смотрителя.
- **Нейросети:** список в `config.js` → `LLM_MODELS`, по порядку: Groq `qwen/qwen3.8-27b` → `openai/gpt-oss-20b` → `openai/gpt-oss-120b` →
  OpenRouter `gemma-4-31b-it:free` → `nemotron-3-ultra:free`. Кончился лимит у одной — берётся следующая,
  а уставшая модель отдыхает, пока провайдер не разрешит снова. Ключи: `GROQ_API_KEY`, `OPENROUTER_API_KEY` в `.env`.
- **Браузер:** свой Chromium с профилем в `data/browser-profile` — окно открывается при запуске, его можно свернуть,
  но не закрывать. В нём выполнен вход в мой аккаунт hh.ru. Слетел вход — в логе «Не вошла в hh.ru», смотритель пишет 🚨,
  войти можно прямо в этом окне (или `npm run login`, когда ассистент остановлен).
- **Откуда вакансии:** со страницы поиска hh.ru. Официальный API поиска hh.ru с апреля 2026 закрыт для обычных пользователей, поэтому читаем сайт — бережно, до 3 страниц раз в полчаса.

## Первый запуск

Можно запускать сразу, даже с пустыми ключами в `.env`:
без нейросети вакансии просто копятся, без Telegram — ждут в базе. Ничего не теряется.

1. База уже создана (Docker-контейнер `hh-postgres`), таблицы тоже.
2. Ключ Groq уже в `.env`. Бот: `MAIN_BOT_TOKEN` и `MAIN_BOT_CHAT_ID` — те же, что `BOT_TOKEN` и `BOT_CHAT_ID` в `MAIN_ASSISTANT/.env`.
3. Смотритель должен быть запущен — без него кнопки под вакансиями не работают.
4. **Профиль:** скопировать `profile.example.md` в `profile.md` и заполнить. `profile.md` не попадает в git.

## Команды

```bash
npm install         # один раз — установить зависимости
npm run db:deploy   # один раз и после обновлений — подготовить таблицы в базе
npm start           # запустить ассистента
npm run login       # войти в hh.ru в окне ассистента (когда сам ассистент не запущен)
npm run dev         # то же, но сам перезапускается при изменении кода
npm run db:studio   # посмотреть базу в браузере
```

## Где что настраивать

| Что хочу поменять | Где |
|---|---|
| Ключи, токены, пароль от базы | `.env` |
| Что искать, регион, опыт, удалёнка | `config.js` → `HH_FILTERS` |
| Поиск вакансий про ИИ и нейросети | `config.js` → `HH_AI_FILTERS` (ИИ в названии) и `HH_DEV_AI_FILTERS` (любой стек + ИИ в тексте); список всех поисков — `HH_SEARCHES` |
| Как часто проверять | `config.js` → `CHECK_INTERVAL_MS` |
| Максимум откликов на вакансию | `config.js` → `HH_MAX_RESPONSES` |
| Минимальная зарплата | `config.js` → `HH_MIN_SALARY` |
| С какой оценки ИИ слать в Telegram | `config.js` → `MIN_MATCH_SCORE` |
| Нейросети и их порядок | `config.js` → `LLM_MODELS` |
| Мой опыт и пожелания для ИИ | `profile.md` (перезапуск не нужен) |

## Ручные кнопки для проверки

Пока ассистент запущен, можно дёрнуть шаги вручную:

```bash
curl -X POST http://127.0.0.1:3002/sync      # только загрузить вакансии
curl -X POST http://127.0.0.1:3002/analyze   # только оценить ИИ
curl -X POST http://127.0.0.1:3002/process   # всё сразу
```

## Лимиты нейросети

Бесплатный Groq: 200 000 токенов в сутки **на каждую модель** (и 8 000 токенов в минуту).
Одна вакансия ≈ 5–6 тыс. токенов → примерно 35 вакансий в сутки. Большинство отсеивается ещё до нейросети,
так что обычно хватает с запасом.
Если лимит кончился — ассистент ждёт следующей проверки, вакансии не теряются.

Ключ Groq общий с kwork, TG и geekjob, а их основные модели — `gpt-oss-120b` и `gpt-oss-20b`.
Поэтому они в списке HH после своей `qwen`: когда HH до них доходит, он тратит их лимит.
OpenRouter (`:free`) — ключ общий с TG и hostaway, около 50 запросов в сутки на всех.

## Файлы

- `index.js` — запуск: сервер и расписание.
- `config.js` — все настройки, кроме секретов.
- `profile.md` — мой профиль для ИИ.
- `services/hh.js` — читает вакансии с hh.ru.
- `services/browser.js` — свой Chromium с профилем и входом в hh.ru.
- `scripts/login.js` — `npm run login`.
- `services/ai.js` — оценка и письмо (промпт).
- `services/llm.js` — подключение к нейросетям и переключение между ними.
- `services/telegram.js` — сообщения и кнопки в боте смотрителя.
- `routes/bot.js` — сюда смотритель пересылает нажатия кнопок HH.
- `services/process.js` — порядок работы: загрузить → отсеять → оценить → отправить.
- `prisma/schema.prisma` — таблица вакансий.
- `.env` — секреты. **Никому не показывать и не коммитить.**
